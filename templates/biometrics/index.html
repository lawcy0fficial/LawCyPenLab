JWT Algorithm Confusion P1 · RS256→HS256

  

    

      
The /api/v6/admin endpoint verifies tokens with algorithms=["RS256","HS256"]. An attacker downloads the public RSA key from /api/v6/public-key, then forges a HS256 token using that public key as the HMAC secret — the server accepts it.

      

        
        
      

      

    

    

      
Attack flow:

      
HEADER: {"alg":"HS256","typ":"JWT"}

      
PAYLOAD: {"username":"attacker","role":"admin"}

      
SIGNATURE: HMAC-SHA256(header.payload, RSA_PUBLIC_KEY)

      

        Server calls jwt.decode(token, public_key, algorithms=["RS256","HS256"])


        It accepts either algorithm — so when it sees alg=HS256, it uses the public key as the HMAC secret to verify, which is exactly what the attacker signed with.
      

      
CWE-347 · Improper Verification of Cryptographic Signature
