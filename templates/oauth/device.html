OAuth Device Code Phishing — RFC 8628

Attacker initiates flow · Victim authenticates at real provider URL · Attacker polls for token
The attacker initiates a device authorization flow and receives a user_code + legitimate provider URL. They send the victim a convincing message: "Click here to authenticate: https://real-provider.com/activate — enter code XXXX-YYYY". The victim authenticates at a real, trusted URL — no phishing domain. The attacker polls until the token is granted.
Attack flow:
  1. Attacker clicks "Initiate Device Flow" → gets user_code + activation URL
  2. Attacker sends victim the phishing message with that code
  3. Victim visits the activation URL and enters the code
  4. Attacker polls "Check Authorization" → receives victim's token
Defenses: Short code expiry (15 min), user confirmation screen showing requesting app name, rate-limit activation attempts, educate users to verify which app requested the code.
